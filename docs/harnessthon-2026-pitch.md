## 나는 이미 투자 하네스를 운영 중이다

- **Hermes** 기반 자가진화 에이전트
- 보유 리스크 **워치독** · 주간 테마 **워치리스트**(HBM)
- **Boradori** — 논문 → 리서치 → Notion 지식 파이프라인
- **Tiered memory + PTR** 컨텍스트 관리

> 정보 파이프라인은 **차고 넘친다.** 문제는 거기가 아니었다.

## 사건 — 나는 Agent를 안 믿고 내 감으로 갔다

- Hermes는 그 종목의 **하락 여지를 짚었다**
- 나는 그 분석을 안 믿고, 내 원칙(지수 -2.5% 룰)까지 어기며 물타기
- → 이후 **2번 더 하락.** 물렸다.

> 믿었다면 따랐을 것이다.
> **못 믿으니, 그 빈틈을 내 감정이 파고들었다.**

<!-- 노트(40초): 실패 공개. "여기서 핵심 질문 — 나는 왜 Agent를 못 믿었나?" -->

## 진단 — 왜 못 믿었나? 응답이 **검증 불가능**했으니까

한 응답 안에 이게 **같은 말투, 같은 자신감**으로 섞여 나온다:

- **[사실]** 공시상 영업이익 ← 비중 실어도 됨
- **[추론]** 그래서 마진 개선 ← 참고만
- **[추측]** 그러니 주가 오를 것 ← 걸러야 함

> 신뢰는 "믿어/안 믿어"가 아니다.
> 응답을 **분해해 어디에 얼마나** 비중을 실을지 — **Calibration(보정).**

<!-- 노트(50초): 발표의 심장 ①. "통신뢰가 아니라 차등신뢰입니다." -->

---

## 접근 — 신뢰는 "똑똑한 Agent"가 아니라 "검증 가능한 Agent"

| 요소 | 적용 | 구현 레이어 |
|------|------|------------|
| **Intent** | 응답에 적정 비중을 싣게 | — |
| **Context** | 내 원칙·보유·신뢰기준 | 메모리 |
| **Constraints** | 출처+날짜·[사실/추론/추측] 라벨·매수추천 금지 | SOUL.md (always-on) |
| **Feedback** | 핵심 수치 DART·KRX 교차검증·확신도 | `response-trust-check` 스킬 (on-demand) |
| **HITL** | Agent는 재료만, 비중은 내가 | — |

## 디버깅 여정 — 두 겹의 함정

1. **스킬**에 규약 → 무시 (스킬은 명시 호출 필요 — 자동 발동 안 됨)
2. **SOUL.md**에 박음 → 무시 → 원인 추적

**함정 ①** `_cached_system_prompt` — **세션 전체 라이프타임 동안 캐시**
→ SOUL.md 수정해도 같은 세션엔 무시 → 게이트웨이 재기동 필요

**함정 ②** 대화 히스토리 **few-shot 효과**
→ 라벨 없는 응답이 2개 쌓인 채로 재기동
→ LLM은 시스템 프롬프트보다 **직전 대화 패턴을 더 강하게 따름**
→ "이 어시스턴트는 라벨 없이 답한다"는 예시가 규약을 덮어버림

3. **명시 프롬프트 주입** (user turn 마지막) → ✅ 작동
→ generation 직전 컨텍스트 → attention weight 가장 높음 → 히스토리 패턴 극복

> 파일을 바꾸는 것 ≠ Agent가 따르는 것
> **언제, 어느 레이어에, 어떤 순서로 주입하느냐**가 전부다.

**Before** (오늘 첫 응답)

## Learning

- **신뢰 가능한 Agent = 검증 가능한 Agent** — 더 큰 모델이 아니라 더 나은 Feedback Loop
- **Constraints 주입에는 두 겹의 장벽이 있다**
  - 시스템 프롬프트는 **세션 캐시** — 파일 수정 후 재기동 필요
  - LLM은 **대화 히스토리를 시스템 프롬프트보다 강하게 따른다** — 기존 패턴이 규약을 덮음
  - 해결: user turn 직접 주입 or 새 대화 스레드(`/new`)에서 시작
- **라벨은 신뢰를 "연기"할 수 있다** — `[사실·99%]`가 틀린 대상에 찍히면 더 위험
  - *(나도 디버깅 중 검증 없이 "종목 틀렸다" 단정했다 틀렸다 — 하네스가 막으려는 그 실수)*
- 내 **물타기(규율 붕괴)조차 신뢰 결핍의 증상**이었다
